# MATLAB 车牌识别工程实例 (License Plate Recognition)

> 项目总览（三种形态、算法流程、完整实测表）见[仓库根目录 README](../README.md)；
> 各轮改动的实测对比见 [`docs/改进记录.md`](../docs/改进记录.md)。

> 配套的**网页版**（浏览器上传照片 → 网页显示识别结果）有两套：
> `../site/`（单文件、免安装，识别在浏览器里跑）和 `../server/`（Python 起服务 + 调本机 MATLAB）。
> 两者都只是壳，识别内核就是本目录的 `lpr_main.m`。

针对**中国大陆车牌**（蓝底白字 / 新能源绿牌 / 黄底黑字 / 白底警用）的照片识别流水线，
包含车牌定位、倾斜校正、字符分割、字符识别四个模块，已在 **MATLAB R2024b** 上实测通过。

## 1. 实测结果

环境：MATLAB R2024b（24.2），Image Processing / Computer Vision / Deep Learning Toolbox 均已安装。

工程自带的 3 张演示图（`images/`，含 -6°、+3.5° 倾斜）：

| 图片 | 期望 | 识别 |
|---|---|---|
| demo_plate.jpg | 京A12345 | 京A12345 ✔ |
| demo_plate2.jpg | 沪B8K9Z2 | 沪B8K9Z2 ✔ |
| demo_plate3.jpg | 粤B1234A | 粤B1234A ✔ |

随机基准集 `bench/`（20 张，随机省份 / 字母 / 数字，倾斜 ±9°，车牌尺寸 0.6~1.15 倍，
带随机模糊噪声），`bench_run.m` 的输出：

```
整牌准确率      : 19/20 = 95.0%
字符准确率      : 139/140 = 99.3%
首位汉字准确率  : 20/20 = 100.0%
字符数分割正确  : 20/20 = 100.0%
平均单张耗时    : 0.15 s
```

`verify_lpr` 会把演示图和基准集全部跑一遍并逐项给出通过 / 失败，`bench_run` 给每张图的明细，
这两个数字都能自己复现。

真实手机路拍 3 张（本地样图，未随仓库提供），整牌 0/3、字符 11/22 = 50.0%、
字符数分割 3/3、定位 3/3 全中（IoU 0.655 / 0.836 / 0.774）：

| 图片 | 期望 | 识别 | 卡在哪 |
|---|---|---|---|
| real01.jpg | 沪AF22933 | `*XF22933` | 绿牌。车牌自带的边框线把垂直投影连成一条，分割失败 |
| real02.jpg | 浙A128T8 | `*ZLEZJ2` | 车牌只有 93 px 宽，单字 8×12 px，分辨率不够 |
| real03.jpg | 京A3454警 | `*A3453警` | 白底警牌。序号与末位 `警` 全对，首位 `京` 被置 `*` |

三张没有一张是定位错位，失败都在分割和识别上。字符数不写死 7 位，而是在 6/7/8 之间自校准
（新能源 8 位牌才不会丢字），代价是个别图会在 7/8 之间摇摆；bench 上这一项已经是 20/20。
分辨率、形近字符和真实成像域的详细分析见[仓库根目录 README](../README.md) 的「实测结果」
和 [`docs/改进记录.md`](../docs/改进记录.md)。要上生产建议走 CNN 方案（见第 8 节）—— **第十轮已经把它做出来了并量过**
（`lpr_main(..., 'Engine', 'cnn')`）：CCPD 真实照片上字符率 **0.064 → 0.145**、位数判对 0.369 → 0.406，
而且更快（0.24 s → 0.14 s）；但自产合成集上 **0.993 → 0.336**，根因是**域不匹配**而不是分类器容量。
所以**默认引擎仍然是模板匹配**，CNN 是可选通路。

## 2. 文件清单

| 文件 | 作用 |
|---|---|
| `lpr_main.m` | **主入口**。串联完整流程，返回识别结果结构体并可视化。`'Engine'` 参数选识别通路：`'template'`（默认，二值化+投影+模板匹配）/ `'cnn'`（固定槽位 + CNN，见下）；`'PlateDigits'` 传已知位数（7/8，例如已判出是新能源绿牌就传 8），留空则取 max(四角实测投影比例, 440/140) |
| `locatePlate.m` | 车牌定位：颜色掩膜（蓝/绿/黄）+ 边缘掩膜 + 多维特征打分选优；候选要过"矩形度 + 底色占比 + 边缘密度"三闸门；两路都没找到真车牌时再走一路**白底车牌**兜底（警用，`whitePlateRegion`，另加"框里有墨迹 + 长宽比 ≤ 3.8"两道判据） |
| `cropPlate.m` | 按定位框裁剪车牌（同步裁剪掩膜） |
| `correctPlate.m` | 几何校正：取掩膜四角，是梯形就用单应变换拉正（透视校正），否则按倾角旋转；高度归一化到 64 px。**透视校正的目标宽度 = max(四角实测投影比例, 440/140) × 64**（只补透视压缩、不制造压缩 —— 检测框比国标还宽时不动手），已知位数时传第 4 入参走 440/140 或 480/140 |
| `segmentChars.m` | 字符分割：Otsu → 去边框 → 垂直投影 → 字符数自校准（6~8）拆分/合并 → 归一化，并输出每段墨迹宽高比 |
| `normalizeChar.m` | 单字符裁边 + 缩放 + 居中到 32×16 画布 |
| `charFeature.m` | 把字符图降采样成定长特征向量（24×12） |
| `recognizeChars.m` | **模板匹配**识别（汉字走 chinese 模板，第 2 位走字母，第 3 位起走「普通字母 + 警挂学领使」，按制式逐位限定候选集） |
| `plateFormat.m` | 车牌制式表：7 位普通（末位可为 `警`）/ 8 位新能源，逐位允许出现的字符（字母表去掉 I、O） |
| `buildTemplates.m` | 用系统字体自动生成字符模板库 `templates.mat`（已随工程提供；除 31 汉字/24 字母/10 数字外还含 5 个特殊字 `警挂学领使`） |
| `templates.mat` | 字符模板库（`buildTemplates.m` 生成，约 48 KB）。**它是模板的唯一来源**，网页版 `../site/src/templates.json` 由 `../tools/export_templates.m` 从这里导出 |
| `slotEdges.m` | **固定槽位边界**：7 位 / 8 位车牌各槽位的归一化左右边界（由 CCPD 统计得到，见 `测试脚本/probe_slot_layout.m`） |
| `slotChars.m` | **按固定槽位切字符**：绕开「二值化 + 垂直投影」，并统一极性（墨迹亮）、逐格对比度拉伸，输出 32×16 灰度格 |
| `recognizePlateCNN.m` | **整牌 CNN 识别**：7 位和 8 位各认一遍，取平均对数概率高的那个（固定槽位没有「数出几个字符」这个信息） |
| `recognizeCharsCNN.m` | **CNN 字符分类**：吃 `slotChars` 的灰度格（不是二值图），按 `plateFormat` 逐位限定候选集，一次前向算完整块牌。需 `charNet.mat` |
| `train_char_cnn.m` | 训练字符分类 CNN（可选，需 Deep Learning Toolbox）。样本目录由 `../tools/make_char_data.m` 生成，14 轮约 7 分钟（纯 CPU） |
| `charNet.mat` | 训练好的字符分类模型（`train_char_cnn.m` 生成，约 0.8 MB）。**可重建产物，不进版本库** |
| `demo_run.m` | 批量处理 `images/` 下所有照片 |
| `verify_lpr.m` | **一键自检**：环境/文件/模块单测/演示图/基准集/可视化/异常处理, 共 30 项 |
| `debug_one.m` | 单张图逐级可视化, 用来判断问题出在哪一步 |
| `bench_eval.m` | 基准集评估函数（被 `bench_run.m`、`verify_lpr.m` 调用） |
| `bench_stage.m` | **阶段归因**评估：每张图归到「正确 / 定位失败 / 分割失败 / 识别失败」里的唯一一个阶段, 按 `category` 分组统计（退化集曲线就是它出来的）。与 `bench_eval.m` 并存, 用途不同。标注里若有真值**四角**(`qx1..qy4`)则走多边形 IoU, 否则退回框 vs 框；`text` 空且无框的行按**无车牌图(负样本)**单独统计, 不进四项分母 |
| `quadIoU.m` | 检测框 vs 真值凸四边形的 IoU（Sutherland-Hodgman 裁剪）。**旋转车牌的轴对齐外接框会把背景框进来**, 拿外接框当真值 `IoU>=0.5` 连完美检测器都过不了（CCPD 实测 14% 的图如此）, 所以真值侧要用多边形 |
| `bench_run.m` | 在 `bench/` 的 20 张随机图上跑准确率统计 |
| `images/` | 3 张演示照片（合成，可直接测试） |
| `bench/` | 20 张基准测试图 + `labels.csv` 标注 |
| `images/expected.csv` | 演示图的标准答案, 自检时用来判对错（可加自己的照片） |

## 3. 运行环境

- MATLAB R2020a 或更高（实测 R2024b）
- **Image Processing Toolbox** —— 必需
- Computer Vision Toolbox —— 可选（`insertText` 渲染模板；缺失时自动回退到 figure 渲染）
- Deep Learning Toolbox —— 可选（仅 `Engine='cnn'` 与 `train_char_cnn.m` 需要）。**没有 GPU 也能用**：32×16 的小网在 16 核 CPU 上 14 轮约 7 分钟

> 编码提示：`.m` 文件为 UTF-8。R2021b 之前的 MATLAB 在中文 Windows 上默认按 GBK 读取，
> 若 `buildTemplates.m` 里的汉字乱码，用编辑器另存为本机编码即可。

## 4. 快速开始

```matlab
cd matlab
addpath(genpath(pwd));

% 单张识别（首次运行若缺 templates.mat 会自动生成）
r = lpr_main('images/demo_plate.jpg');
disp(r.text)        % 京A12345
disp(r.scores)      % 每个字符的置信度

% 不弹窗 + 限制长边加速
r = lpr_main('images/demo_plate.jpg', 'ShowFigure', false, 'MaxSize', 1200);

demo_run            % 批量处理 images/
bench_run           % 跑基准集看准确率
```

返回结构体字段：

```
r.text        识别出的车牌号字符串
r.chars       每个字符的识别结果 (cell)
r.scores      每个字符的置信度
r.plateBox    车牌在原图中的位置 [x y w h]
r.plateImage  校正后的车牌彩色图
r.charImages  分割出的字符二值图 (cell)
```

### 5.3 出错了怎么定位到具体环节

```matlab
debug_one('images/demo_plate.jpg');                 % 弹 6 个子图
debug_one('images/你的图.jpg', 'SavePng', true);    % 同时存成 PNG 便于对比
```

子图依次是：① 原图+定位框 ② 车牌掩膜 ③ 校正后的车牌 ④ 二值化 ⑤ 分割出的字符+识别结果 ⑥ 垂直投影与分割边界。
按图排查：

- ① 没有黄框 → 定位失败，调 `locatePlate.m`
- ③ 歪的 / 车牌被切掉 → 校正有问题，看 `correctPlate.m`
- ④ 字符断断续续、糊成一片 → 二值化阈值问题，看 `segmentChars.m` 的 `thr`
- ⑤ 字符粘连或被切碎 → 对照 ⑥ 看边界切在哪，调 `mergeRuns` 的间隙阈值或 `chooseCount` 的候选范围
- ⑤ 分割正确但个别字认错 → 识别环节，属模板匹配固有误差，考虑换 CNN

## 6. 算法流程

```
原始照片
  │
  ├─① 预处理        ensureRGB / 限制长边
  │
  ├─② 车牌定位      locatePlate.m
  │     ├─ 颜色通道: HSV 阈值 取 蓝/绿/黄 掩膜
  │     ├─ 边缘通道: 垂直边缘(Sobel) + 水平长结构元闭运算（兼容灰度图）
  │     └─ 打分选优: 0.30·长宽比(≈3.3) + 0.15·面积 + 0.25·颜色一致性
  │                 + 0.20·垂直边缘密度 + 0.10·矩形度
  │
  ├─③ 几何校正      correctPlate.m
  │     ├─ 掩膜四个极值点 = 车牌四角(凸四边形的性质, 与旋转/透视无关)
  │     ├─ 四角明显是梯形(边不等长 > 8% 或角偏离直角 > 10° 且车牌够大)
  │     │  → 单应变换拉正(透视校正)
  │     └─ 否则 掩膜上下边界最小二乘拟合倾角 → imrotate 反向旋转
  │
  ├─④ 字符分割      segmentChars.m
  │     ├─ adapthisteq 光照均衡 → Otsu 二值化 → 统一极性(字符=白)
  │     ├─ 清边缘 + 外圈窄带内清超长笔画 + 全图长线开运算 抹掉车牌外框
  │     ├─ 垂直投影 → 连续段 → 合并小间隙
  │     ├─ chooseCount: 先在 7/8 里挑"字符中心间距最均匀"的
  │     │  (固定比例必然把 8 位新能源牌当成 7 位, 所以必须自校准)
  │     └─ normalizeChar 归一化到 32×16, 并输出每段墨迹宽高比
  │
  └─⑤ 字符识别      recognizeChars.m（模板匹配）
                     第 1 位: 31 个省级简称   第 2 位: A-Z(去 I/O)
                     新能源 8 位牌的第 3 位也是字母
                     第 3 位起: 字母 + 数字；按 plateFormat 逐位限定候选集
```

字符匹配得分：`0.65 × IoU(二值交并比) + 0.35 × 相关系数`，汉位置信度低于 0.45 输出 `*` 占位。

## 7. 调参速查

| 现象 | 调整位置 |
|---|---|
| 车牌漏检 | `locatePlate.m` 放宽颜色阈值（`S > 0.30 → 0.20`）、降低 `minArea`、放宽长宽比 `[1.6, 6.5]` |
| 误检到蓝天/蓝色车身 | 提高 `score` 中 `sCol`（颜色一致性）权重，或提高 `minExtent`/`minColorFr` |
| 明明是车牌却提示未检测到车牌 | 把 `locatePlate.m` 的 `minExtent`（矩形度下限 0.50）、`minColorFr`（底色占比下限 0.30）调低 |
| 没有车牌却硬报出一个车牌号 | 反向调高 `minExtent` / `minColorFr` |
| 车牌很大或很小 | `locatePlate.m` 的 `minArea = 0.0008*H*W` |
| 倾斜校正过头 | `correctPlate.m` 中 `abs(ang) < 25` 的上限调小 |
| 汉字被切碎（如"湘""川"） | `segmentChars.m` 中 `mergeRuns` 的 `0.020*W` 调大 |
| 相邻字符粘连成一个 | 同上，把 `0.020*W` 调小 |
| 数字 1、字母 J 的窄笔画丢失 | `segmentChars.m` 的 `thr = 0.05*H` 调小 |
| 字符数不对（多/少一个） | `segmentChars.m` 的 `chooseCount` 候选范围（先 7/8，再退回 6~8）或 `adjustToCount` |
| 斜拍车牌被拉歪 | `correctPlate.m` 的 `hasPerspective` 闸门（阈值 8% / 10° / 高 32 px） |
| 新能源 8 位牌丢字 | `segmentChars.m` 的 `chooseCount`；确认 `plateFormat` 认到了 8 位 |
| 边框被当成字符 | `removeFrame` 里的 `ring`、外圈窄带的 `0.35*W`（横）/`0.60*H`（竖）、全图开运算的 `0.60*W`/`0.85*H` |
| 相似字符混淆（1/4、9/X、3/V） | 换 CNN 通路：`lpr_main(..., 'Engine', 'cnn')`（需先 `train_char_cnn.m` 产出 `charNet.mat`）。注意它在真实照片上更好、在自产合成集上更差，见第 8 节 |
| 白底车牌通道误检（真实照片） | `locatePlate.m` 的 `minWhiteFr`（0.35）/ `maxAspectW`（3.8）；**优先别调这两个** —— 第九轮给白底分支补的 `hasCharStructure`（`valid` 里的 `structOK`）才是真正有效的那个判据 |

## 8. 已知限制与工程化建议

1. **模板匹配对形近字符和低分辨率实拍精度有限**（bench 实测整牌 95.0% / 字符 99.3%，
   难集 75.0% / 86.2%；远距离实拍整牌仍是 0/3）。照片模糊 / 反光 / 低分辨率带来的误差
   无法靠调参消除；近景实拍（车牌占满画面）已经能整牌全对。
   三张实拍样图的失败点也都不在识别器上：`real01` 是分割（车牌自带边框线把垂直投影连成一条）、
   `real02` 是分辨率（车牌 93 px 宽，单字 8×12 px）、`real03` 是牌型没覆盖（白底警牌，现已支持）。
   细节见 [`docs/改进记录.md`](../docs/改进记录.md)。

   分辨率按档扫描的结论是「先崩识别、再崩分割、定位最后倒」，定位到 60 px 以上仍是 100%。
   识别侧的放大锐化把 105~180 px 这段基本填平（w180 整牌 66.7% → 100%、w105 字符率
   70.5% → 95.5%），悬崖下移到 90 px，性质也变了：90 px 以下开始是分割的账，再往下得动分割侧。

   自产退化集的字体与 `templates.mat` 同源，只能当回归自查。灌进 360 张 CCPD 真照片后，
   同样 180~220 px 宽的车牌，自产图字符率 100%、CCPD 只有 6.3%（定位命中后 13.5%），
   差的这 90 个点不是分辨率而是成像域。第九轮试过逐字符局部阈值、`imbinarize('adaptive')`、
   Sauvola，定位命中后的字符率反而从 15.3% 掉到 4.3~8.0%（「字符数切对」从 55.8% 升到 57.5%）：
   局部二值化让分割更好切，代价是把笔画弄糊、模板匹配直接崩。瓶颈在识别，不在二值化，
   下一步不该继续调这两处参数 —— 第十轮已经把下面第 2 条的 CNN 做出来了，结果见第 2 条的状态更新。
2. **CNN 方案 —— 第十轮已做出（`Engine='cnn'`），但默认不启用**。
   实现是 `slotChars.m`（固定槽位切字，绕开分割）+ `recognizePlateCNN.m` / `recognizeCharsCNN.m`；
   样本由 `../tools/make_char_data.m` 生成（真实域 = CCPD 真值四角裁片，合成域 = 系统字体排版 + 退化增广），
   训练脚本 `train_char_cnn.m`。

   **实测（360 张 CCPD + 6 套自产集，详见根目录 README「第十轮补充改进」）**：

   | | CCPD 真实照片 | bench（自产合成） |
   |---|---|---|
   | 模板匹配 字符率 | 0.064 | 0.993 |
   | CNN 字符率 | **0.145** | **0.336** |

   真实照片上 CNN 明显更好且更快（省掉 CLAHE + Otsu + 投影整条链），
   但自产合成集上明显更差 —— 同一个模型在**自己**的合成样本上 93.5%、
   换到 bench 切出来的格子上只剩 43.8%，**差距在域，不在分类器**。
   所以默认引擎保持 `template`，CNN 作为可选通路。

   **要往下走得先解决域差距**：把「bench 切出来的格子」和「训练样本」逐格并排比对，
   定位差距到底出在拉正几何、逐格对比度拉伸、还是退化模型上。
   **这一条第十一轮已经跑完了**：主因是**几何（槽位切偏）** —— 用真值列区间重切后 top1 从
   31.4% 直接到 **96.4%**；对比度只有 +0.112、锐化 +0.048。也就是说**瓶颈在"格子没对齐"，
   不在网络容量**：先把格子对齐，CNN 才有意义。诊断脚本 `测试脚本/probe_domain_gap.m`，
   原始数字 `结果记录/第十一轮_域差距诊断.txt`，完整报告 `评审与改进/第十一轮_技术报告.md`。

   **两个必须知道的坑**（`train_char_cnn.m` 与 `make_char_data.m` 里都有注释）：
   ① `augmentedImageDatastore` **不做数值归一化**，uint8 图读出来是 0~255；不加
   `transform(..., @rescaleInputTable)` 就会「训练吃 0~255、推理喂 0~1」，模型恒定输出同一个字；
   ② 合成车牌里非目标槽位的填充字符必须**按位合法**，否则等于让 CNN 看到「第 1 位是数字」这种
   车牌上不存在的画面。

   公开数据集：CCPD（https://github.com/detectRecog/CCPD ）、CBLPRD-330k。
3. **只支持单层中国车牌**，双层黄牌（挂车 / 客车）、军牌、使领馆牌需要额外处理。
   白底警用车牌已支持（`plateFormat.m` 末位允许 `警`，`locatePlate.m` 有白底兜底通道）。
4. **定位依赖颜色**。夜间、污损、倾斜超过 25° 时可能失败；
   这类场景建议用检测网络（YOLO 车牌检测导出 ONNX，`importONNXNetwork` 调用）替换
   `locatePlate.m`，把检测框直接喂给 `cropPlate.m`，后面模块可完全复用。
5. **定位模块本身没有「这不是车牌」这个输出**。噪声图、棋盘格、路面这些边缘丰富的图，
   边缘通道总能算出一个长宽比合格的块，直接送去分割就会凭空生成一串字符（实测一张纯噪声图
   被认成 `*K884841`）。所以 `locatePlate.m` 末尾有真车牌闸门，候选必须同时满足
   矩形度 >= 0.50、框内车牌底色占比 >= 0.30、框内垂直边缘密度 >= 0.02，否则直接返回空串，
   命令行和网页都会提示「未检测到车牌」并说明原因。白底车牌走另一套闸门
   （白底占比 >= 0.35 + 边缘密度 >= 0.02 + 矩形度 >= 0.40），只在颜色 / 边缘两路都没找到
   真车牌时才启用。
   闸门不只在最后校验冠军，它还参与 `bestRegion` 的选优（主序 = 是否过闸门，次序 = 分数），
   否则边缘通道的高分糊块会先把真车牌挤掉再被自己否掉，整张图报「未检测到车牌」。
6. ~~纯随机噪声图会误检~~ **已修**：闸门判据原本全是尺度无关的（长宽比 / 矩形度 / 底色占比 /
   边缘密度），把图放大到真实照片尺寸后，随机噪声里总能凑出一块样样过关的斑块
   （680×1000 的 30 个种子里 22 个报出凭空捏造的车牌号，90×90 的 11 个）。补上结构证据
   `hasCharStructure`（框内二值化 → 去掉贯穿整行的边框亮线 → 最大墨迹连通域占比 <= 0.25
   且字符带内切得出 2~12 段）之后，实测 680×1000 与 90×90 都是 0/30，四个数据集 50 张图
   逐图逐字节不变；有结构的干扰图（蓝天 / 棋盘格 / 文字 / 路面 / 夜景）本来就挡得住。
   它只做否决、不参与 `bestRegion` 的选优（挪进选优会大面积误杀小号牌：bench 掉到 0.75、
   hard 掉到 0.458、real01 从对 5 位变 0 位），而且它证明的只是「框里有成排的墨迹」，
   不等于「这是车牌」，蓝底广告牌、白底大字标牌一样能过。
   40 张真实无车牌照片上的误检也从 23/40 降到 15/40：把结构证据补齐到白底通道
   （实测它才是误检大头，放行了 10/23）之后，白底误检 10 → 2，代价实测为 0
   （320 张 CCPD 正样本的定位命中仍是 113/320）。别改成去调 `minWhiteFr`（0.35 → 0.489
   同样能挡掉 10/10 个白底误检），它会连带否掉 4 张正样本白底候选，而且那个阈值是照着
   40 张负样本反推出来的，撑不住。
7. **性能**：单张 0.17 s（1000×680）。把 `MaxSize` 限制到 800~1000 px 可再快 2~3 倍。

## 9. 开发中踩过的坑（改代码前建议先看）

这几处都是实测时踩出来的，属于 MATLAB 的坑或车牌图像的特有性质：

1. **`insertText` 对二维灰度图返回的是三通道图**。若直接 `find(out>128)` 按三维数组索引，
   三页数据混在一起，模板会变成空白（本工程第一版就中招，模板全空导致识别乱码）。
   现已统一走 `toBinary()` 转灰度再取二维。
2. **`struct('f', {cellArray})` 会生成 struct 数组**，而不是"字段是 cell 的标量 struct"。
   生成 `alnum` 模板时曾因此得到 1×34 的 struct 数组，报"中间点索引生成了包含 34 个值的逗号分隔列表"。
   要用 `s = struct(); s.f = cellArray;`。
3. **模板与实测字符的长宽比必须归一化**。车牌字体是压缩体（字宽≈0.5 倍字高），
   系统字体是正常比例；`normalizeChar` 默认 `'fill'`（裁掉空白后拉伸填满）把两者拉到同一尺度，
   否则匹配分数只有 0.3 左右，几乎全错。改成 fill 后分数升到 0.7~0.9。
4. **去车牌外框要同时管"完整线"和"断线"**。用 `H/3` 的竖直线做开运算会把数字 1
   （竖线约占牌高 70%）当外框删掉，所以全图开运算的核长取 `0.85*H`；但只靠它会在真实照片上漏 ——
   实拍牌照的边框被 JPEG 与模糊打断成几段（`real01` 的下边框断成 51 px 与 142 px 两段，
   都短于 `0.60*W` 的核长），整条残留下来会把每个字符的墨迹包围盒从 42 行撑到 58 行，
   归一化时字符被纵向压扁，匹配得分从 0.7 掉到 0.3。所以另外加了一道"外圈窄带内清超长笔画"
   （横 `0.35*W`、竖 `0.60*H`，只在车牌外圈 12%/6% 的窄带里生效）。
5. **垂直投影的列阈值不能太高**。数字 1 的撇只占字符高度 5%~8%，
   用 `0.10*H` 会把撇切掉，字符变窄后归一化失真（1 被误判成 4/8）。现用 `0.05*H`。
6. **字符间的间隙（约 0.025~0.04 倍牌宽）必须大于合并阈值**，
   否则相邻字符会被合并；而汉字的偏旁缝隙只有 1~3 像素。合并阈值取 `0.020*W` 比较稳。
7. 生成测试图时，"字高/牌高" 要按真实车牌做成 ~0.65。
   一开始做成 0.32，看着正常，实际会让投影、分割阈值全部失准。
8. **「最高分候选」不等于「这是一块车牌」**。原版 `locatePlate` 只返回得分最高的候选，
   没有拒绝机制，于是任何够大的纹理块都会被当成车牌继续往下走，最后输出一个凭空捏造的车牌号。
   加了矩形度 + 底色占比双闸门后，噪声/蓝天/棋盘格等负例全部被正确拒绝（详见第 8 节第 5 条）。
