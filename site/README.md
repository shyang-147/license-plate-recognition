# 车牌识别 · 单文件网站

`index.html` —— **一个文件搞定**：双击就能用，不需要安装任何东西、不需要联网、
不需要 MATLAB、也不需要 Python。

> 项目总览（三种形态、算法流程、完整实测表）见[仓库根目录 README](../README.md)。

## 为什么做成单文件

之前那版是"Python 起服务 + 调 MATLAB 引擎"，必须把 `server.py`、`start_lan.bat`
等一堆文件**放在同一个文件夹里**才能跑（只把一个 bat 拷出去就会报
`can't open file 'server.py'`）。这一版把整条识别流水线用 JavaScript 重写，
连同字符模板、示例图片全部内联进一个 HTML 文件里，所以：

- 只有一个文件，**不存在"文件没放一起"的问题**；
- 识别在浏览器里完成，**不需要后台服务**，电脑关机了也能用；
- 照片**不会上传**到任何地方，隐私上没有顾虑。

## 怎么用

### 本机打开
双击 `index.html`（Edge / Chrome / Firefox / Safari 都行）。

### 发给别的设备（手机、平板、别人的电脑）
把 `index.html` 用微信/QQ/邮件传过去，在对方设备上**用浏览器打开**即可：

- **安卓**：文件管理器里点这个文件 → "用浏览器打开"。
- **iPhone**：存到"文件"App → 点一下 → 分享 → 用 Safari 打开。
- **Windows / Mac**：直接双击。

> 微信里直接点开会用微信内置浏览器预览，可能显示成源码。
> 请选"用其他应用打开 → 浏览器"，或者干脆压成 zip 再传。

### 同一 WiFi 下给其他设备用（局域网）
双击 `start_lan.bat`，它会用 Python 自带的静态服务器把这个文件夹发布出去，
并在窗口里打印形如 `http://192.168.x.x:8080/` 的地址，
同一 WiFi 下的手机/平板浏览器打开这个地址就能用。

> 这只是"把文件送出去"用的，**识别仍然在各设备自己的浏览器里算**，
> 所以这台电脑哪怕没有 MATLAB、甚至算完就关机，也不影响别人已经打开的页面。

### 放到公网上（有个固定网址，谁都能访问）
因为整个网站就是一个静态 HTML 文件，**任何静态托管都能直接丢上去**：

- [Netlify Drop](https://app.netlify.com/drop)：把 `index.html` 拖进网页，几秒后得到一个网址；
- GitHub Pages / Cloudflare Pages / Vercel：把文件传到仓库里，开 Pages 即可；
- 自己的服务器：丢进网站根目录就行。

### 更新线上演示（GitHub Pages）

本仓库已经开了 Pages，公网地址（手机 4G 也能开）：

**https://shyang-147.github.io/license-plate-recognition/**

## 识别流程（跟 MATLAB 版一一对应）

| 步骤 | 做法 |
|---|---|
| ① 车牌定位 | 蓝/绿/黄底色掩膜 + 形态学闭运算连成块；按长宽比、面积、底色占比、边缘密度、矩形度打分取最高 |
| ② 真车牌闸门 | 矩形度 < 0.50 或框内底色占比 < 0.30 判为假车牌，直接返回"未检测到" |
| ③ 几何校正 | 掩膜四个极值点当车牌四角：四角明显是梯形时用单应变换拉正（**透视校正**），否则拟合倾角旋转校正；高度归一化到 64 像素 |
| ④ 字符分割 | CLAHE 增强 → 大津法二值化 → 去车牌外框/边框残留 → 垂直投影取字符段 → **按“间距均匀度”自校准字符数（6~8，兼容 8 位新能源牌）** |
| ⑤ 字符识别 | 归一化 32×16 → 降采样 24×12 特征 → 与 65 个模板（31 汉字 + 24 字母 + 10 数字）比 `0.65×IoU + 0.35×相关系数`，再扣掉**孔洞数**不一致的罚分；**按车牌制式逐位限定候选集**，极细长的墨迹偏向数字 `1` |

字符模板由 MATLAB 工程的 `templates.mat` 直接导出，所以两版识别结果一致。

> 两版的差别只在两处：白底警用车牌的兜底通道、以及真车牌闸门里"框内必须有成排的字"
> （边缘密度）这条判据，目前只在 MATLAB 版实现；网页版沿用上面的「矩形度 + 底色占比」双闸门。

## 实测

在 `matlab/bench/` 20 张基准图 + `matlab/images/` 3 张演示图上（带倾斜、缩放、模糊的合成车牌）：

| 指标 | 本单文件版 (JS) | MATLAB 版 |
|---|---|---|
| 整牌正确率（bench 20 张） | **95.0%** (19/20) | **95.0%** (19/20) |
| 字符正确率（bench 20 张） | **99.3%** (139/140) | **99.3%** (139/140) |
| 字符数分割正确率（bench 20 张） | 100% (20/20) | 100% (20/20) |
| 演示图 `images/` 3 张 | 3/3 全对 | 3/3 全对 |
| 单张耗时 | 约 150~350 ms | 约 150 ms |

难集（仓库根目录下跑 `python tools/make_hard.py` 生成，每类 6 张）上本版整牌 19/24 = 79.2%：

| 新能源 8 位 | 斜拍（梯形畸变） | 小尺寸 | 夜间 |
|---|---|---|---|
| 5/6 | 2/6 | 6/6 | 6/6 |

> 新能源 8 位这张牌 5/6（掉的那张是首位汉字「黑」被孔洞罚分误判成 `*`），能打高的靠的是
> 字符数自校准 + 识别时按制式限定候选字符集（原来字符数按固定比例估，8 位牌必然被当成 7 位）。
> 斜拍 0/6 → 2/6：透视校正能让字符级明显变好，但拉正时的插值模糊又会拖累模板匹配，
> 这是模板匹配方案的固有短板。

分辨率退化集（每档 6 张同一批牌，把车牌宽度缩到 220~38 px）上本版整牌 **25/60 = 41.7%**、
字符 **67.5%**，比加这两处之前（20/60 = 33.3%、字符 60.5%）高一截；105~180 px 那几档的字符率
从 77~96% 抬到 93~100%，即**原来「先崩识别」的那一段基本被填平**，悬崖下移到 90 px：

| 车牌宽 | 220 | 180 | 150 | 125 | 105 | 90 | 75 | 60 |
|---|---|---|---|---|---|---|---|---|
| 整牌（改前 → 改后） | 6/6 | 6/6 | 5/6 → **6/6** | 2/6 → **3/6** | 1/6 → **3/6** | 0/6 → **1/6** | 0/6 | 0/6 |
| 字符（改前 → 改后） | 100% | 100% | 95.5% → **100%** | 79.5% → **90.9%** | 77.3% → **93.2%** | 72.7% → **81.8%** | 43.2% → **59.1%** | 15.9% → **27.3%** |

示例图 `matlab/images/demo_plate.jpg` 识别为 **京A12345**，逐字符置信度 85/77/53/83/80/69/84%。

## 注意

- 照片里车牌**宽度至少 100 像素**（第八轮之后 105 px 左右也能认，字符率约 93%）；
  太远、太糊、过曝、夜拍、反光都会显著掉准确率。
- 照片里**别出现其它蓝底/绿底矩形物体**（蓝色广告牌、蓝色车身等），否则第一步可能定位错。
- 识别失败时页面会给出具体原因（矩形度不够 / 没有蓝绿黄底色 / 定位到了但切不出字符），
  可以据此判断是照片问题还是算法问题。
- 换照片直接点"选择照片"或按 `Ctrl+V` 粘贴截图；点"清空"回到初始状态。

## 想改代码

源文件都在 `src/`（`index.html` 是它们拼出来的产物，别直接改）：

| 文件 | 作用 |
|---|---|
| `src/lpr_engine.js` | 识别引擎：定位 → 几何校正（含透视）→ 分割（字符数自校准）→ 识别（按制式限定候选集），纯 JS，无依赖 |
| `src/ui.js` | 页面逻辑：选图 / 拖拽 / 粘贴 / 渲染结果 |
| `src/head.html` | 页面结构与样式（含说明文案） |
| `src/templates.json` | 字符模板，由 MATLAB 的 `templates.mat` 导出 |
| `src/demo_plate.jpg` | 内置示例图片（京A12345） |

识别侧有两个可调常数，都对应 MATLAB 侧的同名参数：`HOLE_W`（孔洞数不一致的罚分，默认 `0.04`）、
`USM_AMOUNT` / `USM_SIGMA`（放大到 64 高之后的 USM 锐化，默认 `0.6` / `1.0`，只对"放大"生效）。
评测脚本里可以用 `API.setHoleWeight()` / `API.setUnsharp()` 现场改这两个值做 A/B。

改这两个函数时注意两件事，都是踩过的坑：

- **孔洞数按 `0.5` 二值**，不能用查询特征那套 `0.35` —— 两版的最优二值化阈值本来就不同
  （见 `bestMatch` 里的长注释），混用会把「0 的洞」判没了，罚分反过来伤正确结果。
- `charFeature` 的 288 维特征是**列优先**展开（`index = x*24 + y`）。数孔洞前必须转成行优先的
  24×12 再灌水，否则连通关系全错（这一条是实测出来的：不转的话 hard 从 75% 掉到 62.5%）。

改完在 `src/` 目录下跑：

```
python build_site.py
```

就会重新生成上一层的 `index.html`。
