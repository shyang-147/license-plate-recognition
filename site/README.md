# 车牌识别 · 单文件网页版

`index.html` 一个文件就是全部：双击就能用，不用装 MATLAB 或 Python，不用联网。
识别在浏览器里完成，照片不会上传到任何地方。
项目总览（三种形态、算法流程、完整实测表）见[仓库根目录 README](../README.md)。

## 怎么用

**本机打开**：双击 `index.html`，Edge / Chrome / Firefox / Safari 都行。

**发给别的设备**：把 `index.html` 用微信或邮件传过去，在对方设备上用浏览器打开。
安卓在文件管理器里点它选「用浏览器打开」；iPhone 存到「文件」App 再分享到 Safari；
Windows / Mac 直接双击。微信内置浏览器会把它当源码预览，要选「用其他应用打开」。

**同一 WiFi 下共享**：双击 `start_lan.bat`，它用 Python 自带的静态服务器发布本目录，
并打印形如 `http://192.168.x.x:8080/` 的地址。这只是把文件送出去，识别仍然在各设备
自己的浏览器里算，所以这台电脑没有 MATLAB、甚至算完就关机，都不影响别人已经打开的页面。

**放到公网**：整站就是一个静态 HTML，Netlify Drop 拖进去、GitHub Pages、Cloudflare Pages、
Vercel 或自己的服务器都行。

**更新线上演示**：本仓库已开 Pages，地址是
https://shyang-147.github.io/license-plate-recognition/ ，内容对应 `gh-pages` 分支。
在 `src/` 里重新生成 `index.html` 后同步：

```bash
git subtree push --prefix=site origin gh-pages
```

> git 报 `Failed to connect to github.com:443 over proxy 127.0.0.1` 时，是本机配的代理没开，
> 直连即可：`git -c http.proxy= -c https.proxy= subtree push --prefix=site origin gh-pages`

## 和 MATLAB 版的差别

字符模板由 MATLAB 的 `templates.mat` 直接导出，流水线也逐级对应（见根目录 README 的算法流程表），
两版结果基本一致。差别只有两处：

- 白底警用车牌的兜底通道；
- 真车牌闸门里「框内必须有成排的字」（边缘密度）这条判据。

目前只有 MATLAB 版实现了这两条，网页版沿用「矩形度 + 底色占比」双闸门。

## 实测

bench 20 张基准图加 images 3 张演示图：

| 指标 | 本单文件版 (JS) | MATLAB 版 |
|---|---|---|
| 整牌正确率（bench 20 张） | 95.0% (19/20) | 95.0% (19/20) |
| 字符正确率（bench 20 张） | 99.3% (139/140) | 99.3% (139/140) |
| 字符数分割正确率（bench 20 张） | 100% | 100% |
| 演示图 `images/` 3 张 | 3/3 | 3/3 |
| 单张耗时 | 约 150~350 ms | 约 150 ms |

难集 24 张（`python tools/make_hard.py` 生成）整牌 19/24 = 79.2%：

| 新能源 8 位 | 斜拍（梯形畸变） | 小尺寸 | 夜间 |
|---|---|---|---|
| 5/6 | 2/6 | 6/6 | 6/6 |

新能源掉的那张是首位汉字「黑」被孔洞罚分误判成 `*`。带 8 位牌能打高，靠的是字符数自校准
加上识别时按制式限定候选字符集（原来字符数按固定比例估，8 位牌必然被当成 7 位）。
斜拍从 0/6 到 2/6，透视校正让字符级明显变好，但拉正时的插值模糊又会拖累模板匹配，
这是模板匹配方案的固有短板。

分辨率退化集（每档 6 张同一批牌，车牌宽 220~38 px）整牌 25/60 = 41.7%、字符 67.5%，
比加这两处之前（20/60 = 33.3%、字符 60.5%）高一截。105~180 px 那几档的字符率从 77~96%
抬到 93~100%，原来「先崩识别」的那一段基本被填平，悬崖下移到 90 px：

| 车牌宽 | 220 | 180 | 150 | 125 | 105 | 90 | 75 | 60 |
|---|---|---|---|---|---|---|---|---|
| 整牌（改前 → 改后） | 6/6 | 6/6 | 5/6 → 6/6 | 2/6 → 3/6 | 1/6 → 3/6 | 0/6 → 1/6 | 0/6 | 0/6 |
| 字符（改前 → 改后） | 100% | 100% | 95.5% → 100% | 79.5% → 90.9% | 77.3% → 93.2% | 72.7% → 81.8% | 43.2% → 59.1% | 15.9% → 27.3% |

`matlab/images/demo_plate.jpg` 识别为 京A12345，逐字符置信度 85/77/53/83/80/69/84%。

## 注意

- 车牌宽度至少 100 px（105 px 左右也能认，字符率约 93%）；太远、太糊、过曝、夜拍、反光
  都会显著掉准确率。
- 别出现其它蓝底 / 绿底矩形物体（蓝色广告牌、蓝色车身），否则第一步可能定位错。
- 识别失败时页面会给出原因（矩形度不够 / 没有蓝绿黄底色 / 定位到了但切不出字符），
  可以据此判断是照片问题还是算法问题。
- 换照片点「选择照片」或按 `Ctrl+V` 粘贴截图，点「清空」回到初始状态。

## 想改代码

`index.html` 是 `src/` 拼出来的产物，别直接改：

| 文件 | 作用 |
|---|---|
| `src/lpr_engine.js` | 识别引擎：定位 → 几何校正（含透视）→ 分割（字符数自校准）→ 识别（按制式限定候选集），纯 JS，无依赖 |
| `src/ui.js` | 页面逻辑：选图 / 拖拽 / 粘贴 / 渲染结果 |
| `src/head.html` | 页面结构与样式（含说明文案） |
| `src/templates.json` | 字符模板，由 MATLAB 的 `templates.mat` 导出 |
| `src/demo_plate.jpg` | 内置示例图片（京A12345） |

识别侧有两个可调常数，对应 MATLAB 侧的同名参数：`HOLE_W`（孔洞数不一致的罚分，默认 `0.04`）、
`USM_AMOUNT` / `USM_SIGMA`（放大到 64 高之后的 USM 锐化，默认 `0.6` / `1.0`，只对放大生效）。
评测脚本里可以用 `API.setHoleWeight()` / `API.setUnsharp()` 现场改这两个值做 A/B。

改的时候注意两件踩过的坑：

- 数孔洞时按 `0.5` 二值，不能用查特征那套 `0.35`。两版的最优二值化阈值本来就不同
  （见 `bestMatch` 里的注释），混用会把「0 的洞」判没了，罚分反而伤正确结果。
- `charFeature` 的 288 维特征是列优先展开（`index = x*24 + y`），数孔洞前必须转成行优先的
  24×12 再灌水，否则连通关系全错（不转的话 hard 从 75% 掉到 62.5%）。

改完在 `src/` 目录下跑 `python build_site.py`，重新生成上一层的 `index.html`。
